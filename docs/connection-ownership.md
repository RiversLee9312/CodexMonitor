# 会话连接能力核实

2026-11-03 查阅 OpenAI 官方文档。不能笼统地说“独立 CLI 进程无法连接”。

* 共享服务器：CLI 支持后台服务器和 `--remote`，客户端可使用同一 WebSocket 或本地控制套接字。`--no-daemon` 则绕过共享后台服务器。[CLI 命令与选项](https://learn.chatgpt.com/docs/developer-commands?surface=cli)
* 运行时归属：`thread/list` 包含存储的会话，`thread/loaded/list` 才列出该服务器内存中加载的 ID。`thread/read` 不加载或订阅会话。相同主目录或历史 ID 不足以证明当前轮次由该服务器承载。[App Server](https://learn.chatgpt.com/docs/app-server#threads)
* 恢复历史：`thread/resume` 可继续存储的会话；这不等于接管另一进程正在执行的轮次。文档没有提供按 PID 热接入任意运行中的 CLI 进程的接口。这是对已公开协议能力的判断，而非声称所有 CLI 模式永远不能连接。

应用因此在打开活动或状态未确认的会话时进行只读预检。确认归属才提供连接入口，点击后再次核对。未发现时提示“未找到此会话的应用服务器”，不根据日志来源直接断言 CLI 不支持连接。读取历史和扫描不会开始推理回合。

界面映射依据同一文档的 Items、Item deltas、Warning events、Turn events 与 Errors：推理摘要、明文思考、计划、命令、文件差异、MCP/自定义工具、协作、网页、图像、审查、上下文压缩，以及错误/重试/中断、钩子、模型、MCP 启动、Token 和用量事件。最终 `item/completed` 为权威结果。`summaryTextDelta` 与 `textDelta` 分别累计摘要和明文思考，历史的 `summary` 与 `content` 保持分离；摘要直接显示，明文默认折叠，加密内容始终忽略。协议已给出类型信息，无需用正则猜测摘要。

## 记录来源切换

未连接当前会话时，文件读取器拥有其 transcript；仅连接另一会话的服务器不会改变这一来源。成功加入当前运行时后，app-server 的历史和流式事件成为唯一来源，文件监视仅更新列表信息。手动刷新也从服务器读取，不合并本地条目。

每次选择、连接或断联都会使先前的读取失效。服务器历史读取期间暂存同一会话的通知，按传输接收顺序与每个历史页的水位排除已包含的增量，随后应用新通知。主动断开或服务器意外断开后立即重读本地文件；旧服务器回调、迟到历史响应与过期文件读取均不能覆盖新来源。服务器仍连接但历史读取失败时保留现有视图并报告失败，不偷偷回退到文件。

MSTest 使用可控制的合成传输验证连接前的迟到文件读取、历史/增量交错、未加入会话的通知隔离，以及主动/意外断联、迟到响应和重新连接。真实用户会话没有发送测试指令。


0.1.6 中，本地镜像和服务器原生条目共用 `TranscriptItemAdapter`，实时增量统一进入 `TranscriptUpdates`；服务级通知只进入详情状态区，不混入文件内容。协议类型与兼容边界见 [协议覆盖](protocol-coverage.md)。
